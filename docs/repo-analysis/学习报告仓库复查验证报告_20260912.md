1. **"写报告"≠"掌握技术"**：5 份报告都写得结构完整、分析到位，但学习成果**几乎没有转化为项目代码**。这是典型的"学习报告完成了，但学习没有落地"。

2. **项目能力与学习方向存在结构性错配**：
   - 学习报告重点关注：LoRA 训练、量化优化、多模型支持、画布交互
   - 项目实际聚焦：单引擎（Z-Image Turbo）推理服务 + 安全治理 + 桌面分发
   - 学习报告中的 P0 借鉴点（训练、量化）在项目当前路线图中**没有对应模块**

3. **项目刻意离线化与"自动下载"借鉴方向相反**：fluxgym 和 SDNext 的"自动模型下载"借鉴点，与项目 `HF_HUB_OFFLINE=1` 的离线化策略直接冲突。

4. **Z-Image diffusers 引擎是独立成果**：项目虽有 `ZImageDiffusersEngine`，但这是基于 HuggingFace 官方管线的自研实现，代码中无 InvokeAI 引用，不能归功于学习报告。

### 6.2 根因分析

| 根因 | 说明 |
|------|------|
| **学习与开发脱节** | 学习报告是独立的调研产出，没有与项目开发任务/路线图挂钩，导致"学完就放着" |
| **P0 判定缺乏落地可行性评估** | 初版报告将"LoRA 训练"定为 P0，但项目当前没有训练模块、没有训练路线图，P0 缺乏落地基础 |
| **缺少借鉴落地的跟踪机制** | 没有从学习报告到代码提交的可追溯链路（如 issue 关联、代码注释引用） |
| **报告间交叉验证不足** | SDNQ 在 InvokeAI 和 SDNext 中都存在，但初版未做交叉验证 |
