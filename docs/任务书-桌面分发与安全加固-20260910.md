## 0. 任务目标与优先级

Image_MultiModel 安全模块已相当完整（DCT 水印、完整性自检含行尾归一化、模型权重 fail-closed、密钥已 .gitignore），**但完整性自检无签名、无 enforce——攻击者同时改代码和清单即可绕过，防篡改防线形同虚设**；分发侧停在 Docker/网页，虽有 portable 模型模式但无桌面壳/安装器/增量更新。按以下优先级推进：

| 优先级 | 任务 | 对应报告 |
|---|---|---|
| P0 | 完整性自检升级：Ed25519 签名 + HMAC 回退 + enforce 拒绝启动 | 报告2 §二、§四 |
| P0 | 密钥管理升级：签发侧管理 + 权限自愈 + 离线备份 + 空间隔离 | 报告2 §三 |
| P1 | 桌面化改造：Tauri 壳 + NSIS 安装器 + 模型分卷 | 报告1 §一~§四 |
| P1 | 增量更新（仅应用代码层） | 报告1 §阶段5 |
| P2 | 发布门禁五步 + 冒烟前诊断脚本 | 报告2 §4.1、§4.2 |
| P2 | 闭源编译评估（水印模块 Cython .pyd） | 报告2 §五 |

**原则**：客户端侧无"不可破解"，追求"成本 > 收益 + 可举证"（报告2 §1.1）；enforce 的前提是验签信任根可信，先定密钥分发再开 enforce（报告2 §七-6）。

## 3. 分阶段任务清单

### 阶段一：完整性自检升级——签名 + enforce（P0）

1. **生成清单签名密钥对**（参照 SeedVR2 `scripts/generate_manifest_signing_key.py`）：
   - 私钥（Ed25519 PEM）→ 签发机本地 + GitHub Secret（如 `MANIFEST_SIGNING_KEY_B64`），**不入库**
   - 公钥 → 仓库内 `manifest_signing_public_key.pem`
   - **离线备份私钥**（报告2 SOP-17），备份后本机副本删除

2. **写签名脚本** `scripts/sign_integrity_manifest.py`：
   - 读现有 `integrity_manifest.json` → Ed25519 签名 → `.sig.ed25519`；HMAC-SHA256 回退 `.sig`（64B 密钥，权限 0600/icacls 收紧）
   - **签名后立即用内置公钥回验，错配即 fail**；构建期断言 payload 公钥 == 仓库公钥 SHA256 一致（报告2 GOTCHAS #97）
   - 复用现有 `_compute_file_sha256` 行尾归一化逻辑（**不要改动**，改了就破坏跨平台一致性）

3. **升级 `integrity_selfcheck.py`**：
   - 验签步骤：先验 Ed25519 签名（失败回退 HMAC），再逐文件比对哈希
   - config.yaml 增加 `integrity_selfcheck.enforce: true` → 验签/哈希失败**拒绝启动**（当前只 log，改为 fail-closed）
   - 保留现有 skipped 告警（清单漂移可见），enforce 下不允许 skipped 静默裸奔

4. **密钥分发配套**（报告2 SOP-19）：CI Secret 注入签名（不用打包机自签）；公钥入包；**先定密钥分发再开 enforce**——否则分发版验签失败直接无法启动。

**验收**：
- [ ] 篡改任一核心 .py 1 字节 → 自检失败且 enforce 拒绝启动（真机便携包）
- [ ] 同时篡改清单 + 代码 → 无私钥无法重签 → 验签失败拒绝启动
- [ ] 签名回验 PASS + 公钥一致性闸门生效
- [ ] 行尾归一化未回归：Windows 生成清单、Linux 校验哈希一致

### 阶段二：密钥管理升级（P0）

1. **权限自愈**（报告2 §3.3）：`get_secret_key()` 每次读取调用 `harden_secret_file_permissions()`（POSIX 0600 / Windows icacls 去继承）；测试护栏：临时目录跳过 icacls。
2. **空间隔离定案**（报告2 SOP-18）：正式分发版**不注入** `SEEDVR2_WATERMARK_KEY` 等价密钥；分发版每机首启自生成实例水印密钥。代价明示：官方无法跨实例验证用户机产物签名，但无人能伪造官方可验水印。企业场景 env 注入统一密钥。
3. **水印失败策略**（报告2 §六）：从 fail-open 改为三级：**重试 1 次 → 写 `.provenance.json` 侧车元数据（默认）→ 阻断产出（block 档）**，记审计事件；config.yaml 增加 `watermark.failure_mode`。
4. **合规声明**：`PRIVACY_POLICY.md` 写明水印密钥只存本机、不随仓库分发（对照现有补段）。

**验收**：
- [ ] 密钥权限已收紧；读取自愈单测通过
- [ ] 发布包内无 `.watermark_key`/私钥/`seedvr2_secret` 等价物（拆包验证）
- [ ] 水印失败默认走侧车，可配置阻断；审计有记录

### 阶段三：桌面化改造（P1，按报告1全流程）

1. **分层定案**（报告1 §一）：
   | 层 | 内容 | 更新方式 |
   |---|---|---|
   | 壳 | Tauri v2（新增 `desktop/src-tauri`） | 随安装包/增量包 |
   | 应用代码 | FastAPI + 前端模板 | **增量更新**（每次发版只换这层） |
   | 运行时 | WinPython + 非 torch 依赖 | 安装包提供 |
   | 计算依赖 | PyTorch + comfy_kernel wheels（离线装） | 安装包提供 |
   | 模型权重 | pretrained_models/（Z-image 等，体积大） | 安装包提供，可自行替换 |
2. **Tauri 壳必需能力**（报告1 §阶段2）：原生窗口、**系统托盘**、Toast、文件拖拽、窗口状态记忆、**单实例**、**后端崩溃自动重启**；显式关闭默认打开浏览器、子进程 `CREATE_NO_WINDOW` 隐藏控制台（报告1 §四-6）。
3. **NSIS 安装器**（报告1 §阶段3）：检测并终止运行中的程序 → 解压数据分卷 → 写注册表/开始菜单/卸载项；卸载清 `HKCU\Software\ImageMultiModel`、`Uninstall\ImageMultiModel`、`%APPDATA%`、快捷方式。**脚本 UTF-8 with BOM**（报告1 §四-8）；许可协议文本非空、README 页能显示。
4. **GitHub Release 分卷**（报告1 §阶段4）：模型在 pretrained_models/，按 **1900MB** 切片（单文件 ≤2GB 硬约束，留余量）；命名 `ImageMultiModel-Data.7z.001/002/...`；`SHA256SUMS` 覆盖**全部**资产（含每一卷）；发布后 `gh release view --json assets` 数资产 + `gh release download` 回读哈希比对（报告1 §四-1：漏传分卷 = 发布事故）。
5. **增量更新**（报告1 §阶段5）：托盘"检查更新" → 最新 tag → 对比版本 → 下载 app zip → **SHA256 校验** → **原子换载**（备份→替换→重启）→ 失败回滚。三易错点：① native-tls；② 先停 Python 进程再换载（日志句柄 `os error 32`）；③ 清理孤儿进程。
6. **版本单一来源**：`pyproject.toml`（当前 1.2.2 in config.yaml，统一到 pyproject）。

**验收**：
- [ ] 干净机器：安装→启动（无浏览器/无控制台）→修复→检查更新→卸载无残留
- [ ] 增量更新全链路 + 失败回滚 + 每步可见反馈
- [ ] 分卷发布资产齐全、SHA256SUMS 逐行一致
- [ ] 托盘/单实例/崩溃自启实测

### 阶段四：发布门禁五步 + 诊断脚本（P2）

参照报告2 §4.1 门禁五步，构建机真跑：
```text
① 构建（build_portable_bundle 等价）
② 拆包验证：清单条目完整、公钥验签 PASS
③ 负向断言：包内无 .watermark_key/私钥/.py 残留（若闭源编译）
④ 篡改模拟：改任一模块 1 字节 → enforce 拒绝启动
⑤ 冒烟启动：便携 python 真实启动自检，Ed25519 验签 PASS
```
- **诊断脚本进仓库**（报告2 §七-3）：`scripts/diag_*.py` 用便携 python 直接调验签函数逐环节打印（import OK / manifest / sig / pub / VERIFY=True|False），CI 只调脚本路径；**超过 3 行逻辑一律落脚本，不内联 `python -c`**（YAML 块标量易碎）。
- **辅助 job 纪律**（报告2 §七-4）：不稳定的"独立快速诊断"job 宁可并入主链，避免拖红整体。

### 阶段五：闭源编译评估（P2，报告2 §五）

- 评估将 `watermark.py`/`watermark_gpu.py` + `security/` 用 **Cython 编译 .pyd + 符号改名 + 注释剥离**，发布包无 .py/.c 源码
- **必须公开声明**（报告2 §5.2）：README/NOTICE 写明"某组件为闭源构建"，隐瞒比公开更伤信任
- Apache-2.0 下二进制分发不要求附带源码（报告2 §5.1），公开仓库保留源码即可

**验收**：发布包可拆包验证无源码残留；README/NOTICE 有闭源声明；水印功能回归测试通过。

## 4. 避坑指南（本项目专属 + SeedVR2 踩坑引用）

1. **便携 python 丢 cryptography**（报告2 GOTCHAS #98）：7z 解 NSIS 后 WinPython 预装 cryptography 丢失 → Ed25519 验签不可用 → enforce 下分发版拒绝启动。**`cryptography==50.0.1` 显式钉装**进便携依赖清单。
2. **enforce 与密钥分发必须一起定**（报告2 §七-6）：先定 CI Secret 注入 + 公钥配套闸门，再开 enforce。
3. **行尾归一化是已修复资产**：新加模块进清单前确认沿用 `\r` 删除逻辑（本地绿 CI 红的经典来源）。
4. **模型分卷漏传**（报告1 §四-1）：安装器解压数据必然失败。发布后第一件事核对资产数量。
5. **NSIS 中文乱码**（报告1 §四-8）：UTF-8 with BOM；发布前逐页截图验证。
6. **CI 运行器 Python 裸奔**（报告1 §四-2）：签名/验签脚本用啥装啥，一次装全（含全部 import）。
7. **更新三连坑**（报告1 §四-7）：native-tls / 版本号旧值 / 静默失败——每步可见反馈。
