## 3. 必答三问

### Q1：`IMM_FAKE_ENGINE=1` 替换在哪一层？保真度如何？

**替换点：引擎工厂层**——`model_registry.create_engine_instance`（`app/integrated_app/model_registry.py:116`）在环境变量生效时返回 `FakeEngine`（`app/integrated_app/testing/fake_engine.py`），它完整实现 `ImageEngine` 协议（load/unload/infer_txt2img/cancel/is_ready），**写出真实的 1×1 PNG 文件、尊重取消、触发进度回调**。

这是**足够低的测试缝**：其上的 路由→鉴权→校验→LoRA 兼容矩阵→过载拒绝→任务队列→worker→SSE 进度→历史落盘→输出管理 全部执行真实代码。E2E **不是"测 mock"**。唯二有意旁路：① VRAM 调度器 batch 钳制（`generation_service.py:310-317`，注释写明理由：CI 无真实水位会导致随机钳制 → flaky，取舍合理）；② 引擎内部 torch/comfy 路径（即上面 0% 模块）。

**提升方案**：真机路径由 gpu-smoke 覆盖（见 Q2）；`seedvr2_service`（0%）若列为交付功能，需在 gpu-smoke 中加一条超分冒烟。

### Q2：无真机 GPU 测试如何防回归？现状与最小可行方案

**现状（实测，有两处修正）**：
1. `gpu-smoke.yml` + `scripts/gpu_smoke_minimal.py`（7524 字节）**确实已提交**（commit `e1cd31c`，设计对齐 SeedVR2-lite：runner-precheck 优雅跳过 + 独立 workflow 不阻塞发版）。
2. **但本地 main 领先 origin/main ≥5 个提交，该 workflow 尚未推送到远程**——`gh api` 实测远端 404（`workflow gpu-smoke.yml not found on the default branch`）。提示词「已在仓库内提交」仅本地为真，**远端 CI 现实中不存在此防线**。
3. gpu runner 注册与 `REPO_ADMIN_TOKEN` secret 均未验证。

**结论**：当前真机推理覆盖仍为零（远端视角），但补齐成本已降到"一次 push + 一次 runner 注册"。最小可行形态即已写好的 gpu-smoke（拉服务 → `gpu_smoke_minimal.py` 最短样本 → CUDA 断言 → 报告 artifact），无需重设计。

### Q3：marker 清理还是补用例？

**都不需要**——实测 marker 全部在用（§2.1）。原命题失效。低成本 CI 校验仍值得加（防未来退化）：预检脚本中加一行 grep，某声明 marker 使用文件数为 0 时告警。
